# Decision Crystal: video-studio 媒体来源架构（风格绑库 + 按时长的节奏时间轴）

Date: 2026-07-03

## Initial Idea

用户："你来看看整个架构，按照正规视频生成流来对比一下，是不是我们最开始就有架构级别的错误？"

后续提出方案："plugin 支持素材库，离线或者在线；根据风格进行匹配；像我们现在用的动漫风，如果没有匹配的在线库、离线库（自己也没有积累多少），就得消耗额度来做了，这是每一次 video-make 之前预处理的一个；现在的风格，比如动漫已经入了配置文件，这个关联的 Stock 也可以一并入配置，就不用每次都预处理。这样就可以在保留风格多样化的同时，也支持外部素材库来减少成本。"

## Discussion Points

1. **架构病根**：初始假设=按 beat（旁白段）配一个画面没问题。发现（代码证据：`director` 在 `TTS` 之前跑、`beat 时长 = 旁白音频长度`、`ffcmd.max_shots` 说 44 秒能放 55 镜但 director 只给 2–4 镜）=**视觉粒度被旁白 beat 绑架、镜头数不由时长推导** → 渲染层只能把少数镜头摊/循环/hold 到实际时长。决定=这是 ⑤（静图呆）⑧（图表挂50秒）⑨（视频循环8次）的**共同根**，不再打补丁，改走按时长的节奏时间轴。
2. **正规流参照（剪映）**：WebFetch 证实剪映一键成片=时间轴节奏由**模板/音乐节拍**驱动、不由文案句子长度；素材从**池子选、不生成**。借鉴：节奏优先的槽位时间轴（~5–6 秒一个镜头）、镜头数按时长推导、每镜扣当下内容。
3. **成本翻转**：ep005 实测=12 个视觉撑 420 秒（平均一个画面 35 秒，这就是呆/循环的来源）；正规密度 ~70 镜 ≈ 6× 生成费。用**素材池**（剪映省钱的本质）把 b-roll 变便宜。
4. **写实+stock 验证（spike）**：复用 ep005 女声音频+字幕、66 个免费 Pexels 镜头按台词内容匹配、~6 秒节奏拼成完整一期。用户看后"还不错"。暴露 query-writer 偶尔**照字面拍**（把"工程系数/代码换算"搜成 coding/whiteboard 办公镜）→ 需约束。同时暴露两个 spike 拼接 bug：结尾旁白被截、少数片段重复。
5. **媒体来源分层（用户方案）**：plugin 支持素材库（在线 API / 离线本地池）；风格与库的绑定写进 config；渲染时库优先、无匹配才付费生成兜底。保风格多样 + 降本。
6. **风格是不变量、来源不是（用户纠正 AI）**：AI 曾说"一期要么全库要么全生成、别混"。用户纠正："生成也可以写实"。结论=一期内**来源可自由混**（库+生成并存），只要**生成 style-aware、按该期风格产出**；source 与 style 正交。

## Rejected Alternatives

- **plugin 层强制切 stock 版**：拒绝——改成"风格绑库、库优先、生成兜底"，stock 只是众来源之一。
- **"一期要么全库、要么全生成"（来源单一）**：拒绝——风格一致才是不变量，来源可自由混。Rejection scope：拒的是"来源单一"这条；不拒"一期内风格必须一致"（这条保留）。
- **提示词 hardcode 拦坏构图（如"逆人流/挥手"）**：拒绝——用户："模型理解场景不到位，你 hardcode？搞笑呢？"（hardcode 治不了模型的场景理解，是打地鼠）。
- **把 ⑨（视频不循环）当独立 patch 单做**：拒绝/合并——⑨、⑧ 都是"beat → 按时长的 N 个不同视觉"的特例，折进本架构一次做对。

## Decisions (machine-readable)

- [D-001] 架构病根 = 视觉粒度被旁白 beat 绑架、镜头数不由时长推导；重构为"按时长推导的节奏时间轴"（每镜约 5–6 秒，每镜扣当下旁白内容）。
- [D-002] 分镜/来源决策移到 TTS 之后（每段真实时长已知）再定，不再在 director storyboard 时凭感觉给固定镜头数。(linked: D-001 — 病根的直接修法)
- [D-003] 媒体来源做成独立一层，按风格路由：库优先（在线 API / 离线本地池），无匹配才付费生成兜底。
- [D-004] "风格 → 素材库"的绑定写进 config（如动漫、写实各绑各的），不每次 video-make 重决定。
- [D-005] 一期内的不变量是"风格一致"、不是"来源单一"：来源可混（库+生成），但生成必须 style-aware、按该期风格产出。(linked: D-003 — 来源分层的约束)
- [D-006] 在线库 = 写实/实拍专属（Pexels / Pixabay / Coverr，CC0 免费、有 API）；动漫等无在线库的风格 → 只能生成，或自建离线池。
- [D-007] 内容匹配 = query-writer（LLM，走 claude -p）：把每个旁白窗口翻成可拍场景查询（抽象论点 → 跑步代理画面）；硬约束只出"运动/人物/自然"、禁"办公/屏幕/代码/抽象"；再加 L2 用候选的 slug 描述重排、筛掉跑偏。
- [D-008] 拼接硬规则：视频轨 ≥ 音频轨（旁白绝不被截）；无镜头重复/循环（每镜不同 + 跨集去重）；单段/单镜时长封顶。
- [D-009] "写实 + stock" 确立为一个可行的风格选项；不在 plugin 层强制 stock，它只是众风格之一。
- [D-010] 所有 LLM 调用一律走 `claude -p`，永不换直连 API（项目硬规则，重申）。
- [D-011] **workspace（内容项目，如 running-class）默认风格改为"写实"**（写进 workspace config）；plugin 本身不设强制默认风格，默认由 workspace 决定。
- [D-012] **自建离线素材池纳入本次重构 scope**（给动漫等无在线库的风格用：一次性生成、打标、跨集复用）。
- [D-013] **每个风格各留一个固定人像（character_ref）**：需要生成出镜人镜头时用它保证跨镜/跨集统一（写实风=写实主持人像，动漫风=女教练）。b-roll 走库、出镜人镜头走生成（用该风格 ref）。(linked: D-005 — 风格一致前提下的出镜人一致)

## Constraints

- 成本敏感：库优先（免费/便宜），只在无匹配时才付费生成。
- 已提交的命名修复 + ⑤⑥⑦③⑧ 是"生成路径"的止血，保留（生成兜底路径仍会用到）。
- LLM 一律 `claude -p`（D-010）。

## Scope Boundaries

- IN: 媒体来源分层（库在线/离线 + 生成兜底）；"风格 → 库" config 绑定；按时长的节奏时间轴（分镜移到 TTS 后）；query-writer + 约束 + L2 重排；视频轨 ≥ 音频轨；镜头去重；"写实+stock" 作为一个风格落地；workspace 默认风格=写实（D-011）；自建离线素材池（D-012）。
- OUT: ① 脚本长度门 / ② 图表安全区配置化（用户"排后面"）；Gap1 大纲耗尽引导 / Gap2 重规划保护 done 期（排后面）；已完成并提交的命名修复 + ⑤⑥⑦③⑧（已交付，非本次重构范围）。
