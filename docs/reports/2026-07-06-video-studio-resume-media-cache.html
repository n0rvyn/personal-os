video-studio 渲染管线 resume（媒体缓存）

2026-07-06 · personal-os / video-studio · self-pacing 自主执行验收
一句话结论：崩溃/迭代重渲不再从零重付费的 resume 功能全部落地并验证——15 个任务、两层机制（钉死 prompt 源 + 媒体内容寻址缓存）+ 两条重渲路径，全套件 986 passed / 3 skipped / 0 failed；执行中经两轮独立审计各抓出真 bug（先是 2 个测试 bug，再是 2 个 doc 模式 must-fix），全部修复且复审确认闭合。未提交（按约定等你说 commit） 付费 LIVE 双跑验证由你择时

背景 · 要解决什么

M区 LIVE 渲染在最后一步因豆包欠费 403 崩溃，丢掉 6 个 S2V 视频（各 ~108900 tokens）+ ~50 张图 + 40 分钟。根子：每次渲染开一个带时间戳的新 scratch 目录，跑成功就删、崩了留着但下次重跑又开全新的、根本不看上次那个——已付费媒体成了孤儿。目标：崩溃续跑 + 改几个 beat 增量重渲，都复用已生成的贵付费媒体。

交付了什么（What shipped）

核心判断（brainstorm 挖出，是本次架构的关键）：光缓存媒体不够——分镜/脚本是 LLM 现生成、每次 prompt 都变，按 prompt 当缓存键会全 miss。所以是两层：

过程 · 15 任务 + 两轮抓 bug

用 self-pacing 自主执行器分两段跑（batch 0 → batches 1-3），plan-verifier 事前 2 轮修订（抓 3 个纯 UT 会漏的集成 blocker：--episode 误推进 cursor、seams 撞 keyword-only run_pipeline、wrapper 丢 late-bind style_prefix 写）。执行后两轮独立审计各抓出真问题：

症状真因修法

第 2 轮 — implementation-reviewer 抓出 2 个 doc 模式 must-fix（真 bug，fixture-only e2e 照不到）

根因同一类：A 层"复用"分支只还原主产物，丢了 live 分支对 ctx 做的副作用；而 e2e 只跑 fixture 模式（走 pass-through 分支），所以 986 绿是假绿。

#问题后果修法
MF#1分镜 durable/SPIKE 复用没把 visual_type/video_prompt/chart/color_grade 回填到 ctx["beats"]doc 模式续跑直接崩（step_shotplan 读 beat["visual_type"] → KeyError）——正是功能存在的核心场景抽共享 _backprop_visual_fields()，live + durable + SPIKE 三分支统一调

堵根：加了 3 条 doc 模式续跑测试（beats 不带 visual_type、驱动两条复用分支），直接断言复用后 beats 带回 visual_type/video_prompt/chart + 卡片字段还原——正是修复前缺失、会挂的行为。

决策记录（架构层，4 项已定）

决策选择依据
复用姿态默认复用，--fresh 强制全新正常渲下一集缓存空、天然不受影响；复用只在重跑同集时触发（正是想省钱的场景）
上游失效输入指纹 stamp 自动失效改 persona/config 重渲免记 --fresh，否则静默拿旧分镜
缓存深度只存原始付费素材，不存 ffmpeg 中间片40 分钟痛 ~95% 是付费素材；ffmpeg 重跑几分钟免费；让运镜/调色免费微调不触发重付
重渲触发崩溃续跑走 cursor（自动）；定向加 --episode选择机制 ⊥ 缓存机制（Make/Bazel 通行做法）；select_next 够不到 done/cursor 后方的集
