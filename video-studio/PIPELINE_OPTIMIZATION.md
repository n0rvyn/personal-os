## 1. 脚本/文案（Stage 0 规划器）
- **当前程度**：⬜ 手写 fixture（`beats.fixture.json` / `beats.long.fixture.json`）。
- **已做 & 结论**：脚本质量直接决定成片；钩子、要点、节奏都在脚本层。
- **后续方向**：Stage 0 = `pdftotext` 抽教材 → LLM 提模块/分集 → 用户锁 syllabus → 每集 LLM 写「有钩子、可总结」的脚本。脚本里就该埋：开头 3 秒钩子、结尾 3 要点。

## 2. 分镜/配图（storyboard）
- **当前程度**：✅ `lib/storyboard.py`，`claude -p sonnet` 读每句台词产 shots{prompt, shot_type, with_character} + keywords。
- **已做 & 结论**：内容感知出图（睡眠→卧室闹钟空镜、收尾→背影）；变机位（全景/特写/跟拍/脚步/过肩/背影）；7/19 空镜打破"大B脸"；相邻同母题连续。
- **跑在转发模型上（环境事实）**：`claude -p --model sonnet` 经用户自建 ModelProxy（`ANTHROPIC_BASE_URL=localhost:9090`）转发到其选定后端（非官方 Sonnet，疑 MiniMax 系）。所以**文本理解偏弱 + 偶发坏 JSON + 慢（曾单次 >360s）是常态**，解析与超时必须容错（下条）。
- **分镜复用钩子（提速）**：每次渲染都重跑这步慢 LLM 很耗。driver 每次把分镜结果存 `.spike/storyboard.json`；`SPIKE_STORYBOARD_JSON=<path>` 让调色/调时间重渲时**直接读存档、跳过 LLM**（校验 beat 数匹配）。镜像 `SPIKE_S2V_CLIP` 复用模式。实测短片复用渲染 ~2min（省掉 6min+ 分镜调用）。
- **JSON 容错（POC6 修，重要）**：实测经常**漏掉数组最后的 `]`**（也偶有结尾多逗号），旧的 `rfind(']')` 抓错括号 → 整条崩（曾 3/3 失败）。改 `_extract_json_array`：**字符串感知**扫括号深度（不被中文 prompt 里的 `[]` 干扰）、未闭合则按开栈补 `]`/`}`、清结尾逗号。另把 `claude -p` 超时从 240→360s 且 `TimeoutExpired` 进重试（旧版超时直接崩）。真实坏样本存 `lib/tests/fixtures/storyboard_truncated.json` 防回归。
- **后续方向**：match cut（构图/动作匹配剪辑）；镜头节奏（见#13）；空镜比例调参（见#14）；风格库（多风格切换）。

## 3. 人物一致
- **当前程度**：✅ image-01 `subject_reference` 锚定 character_ref。
- **已做 & 结论**：88s、约 20 张不同生成图，开头/中段/结尾同一个人，不漂。
- **失败/教训**：subject_reference 视频用 `image:[url]` 数组、图用 `image_file` 标量——格式不同（见 SPIKE_FINDINGS）。
- **下载存盘按真实类型（bug 修，2026-06-29）**：MiniMax 返回的是 **JPEG 字节**，旧代码一律存成 `.png` 名——文件名撒谎。改 `media_image._download` 嗅探魔数（FFD8=jpg/89504E47=png/WEBP/GIF）按真实扩展名落盘并**返回实际路径**，`gen_still` 返回该路径、driver 用返回值喂 ffmpeg（不再假设 `.png`）。真机验过：请求 `.png` → 落 `.jpg`、`file` 认 JPEG、短片渲染绿。
- **后续方向**：S2V 用同一 ref 验真一致（#4/POC7）；风格固定下的人物库。

## 4. 视频镜头 S2V
- **当前程度**：✅ `lib/media_video.py`，S2V-01 真跑通、下载、6s；同人一致验过（POC7）。
- **已做 & 结论**：**模型必须 `S2V-01`**（Hailuo T2V/I2V 报 2013 不支持）；响应扁平（task_id/status/file_id 顶层、download_url 在 file 下）；**实际出 720p**（ffmpeg 放大到1080p）；不稳/超时**回退静图**（6 分支判定，已验）。额度 21/周。
- **POC7 同人一致（验过）**：同一 character_ref → 静图人物镜 + S2V 动态视频，肉眼同一人（脸型/眼镜/外套/气质一致），无身份漂移。帧间轻微变化（眼镜偶尔不明显）但识别始终同人。装置 `.spike/poc7_probe.py`，对比图 `.spike/poc7_consistency.png`。
- **决策（用户拍板 2026-06-29）：S2V = 选择性增强**。只给关键动作镜（如跑姿示范），一条片 1–2 个，其余静图 Ken Burns。现 pipeline 已是此法（仅 `visual_type=video` beat 走 S2V），明确为默认策略。21/周额度不够每镜都用。
- **后续方向**：多 S2V 镜头的预算门（Stage 1，单片 S2V 数上限）；时长/分辨率协商。

## 5. 图表
- **当前程度**：✅ `lib/media_chart.py` matplotlib 真渲染，PingFang，1920×1080。
- **已做 & 结论**：数据真实非 AI 生成；忠实。
- **后续方向**：数据动效（逐行揭示、数字滚动到位、进度条）；图表美化（对标 refactoring-ui）；与台词数字一致性校验（忠实门 #17）。

## 6. 动态字幕
- **当前程度**：✅ `lib/subtitle.py build_ass` 样式B（加粗白字+干净描边+柔投影，无框）+ 关键词强调（金色+放大+弹入）。
- **已做 & 结论**：关键词由分镜那步 LLM **选择性**标注（一句0–2个、可为空、不硬凑，6/12空）；用 libass ASS 标签，`mux_final_ass_cmd` 烧录。样式B 用户选定。
- **后续方向**：更丰富的 kinetic typography（逐字弹、位置变体、长句双行）；强调动效库；字幕安全区/多端适配。

## 7. 旁白音色
- **当前程度**：✅ `lib/media_tts.py` voice=`male-qn-jingying-jingpin`(精英青年-精品) + `ffcmd.voice_polish_cmd`（轻压缩+loudnorm）。
- **已做 & 结论**：音色选型是 voice 质感的真杠杆（不是 DSP）；MiniMax 303 音色，按**字数×模型**计费、**不按 voice_id**，换音色免费；选 5 因更贵+断句好+与播客一致。env `VIDEO_VOICE_ID` 可覆盖、`synth(voice_id=)` 可传。
- **失败/教训**：**干声 DSP 调音色收益极小**——厂家 TTS 已母带处理；loudness-matched A/B 用户听不出音色差，只听得出响度差。所以只保留响度归一（"看不见但正确"）。
- **后续方向**：voice_id 进栏目级 config（不同栏目/主题换音色）；情绪/语速按内容微调；音色克隆（用真人主播声）。

## 8. 声音设计（SFX / 环境音 / BGM 情绪）
- **当前程度**：❌ 合成 SFX 验为负、放弃；🟡 真 BGM = 后期优化项。
- **失败/教训（重要）**：**合成 whoosh/tick/环境噪 叠进去 = 帮倒忙**。① 环境噪叠干净旁白上像"录音底噪/音频故障"；② whoosh/tick 没卡在真事件上=乱入；③ 这种**平静、电影感、旁白驱动**的知识片，调性上就不该有综艺/vlog 那套音效。→ 用户原话"乱入、没提升、反倒像音频有问题"。
- **结论**：此类片子声音质感 = **旁白（已搞定）+ 一条对味的真音乐**，不是音效。
- **后续方向**：真 BGM 选源（用户提供 / 免费可商用库 Pixabay/YouTube Audio Library），跟旁白做 ducking（#15 已就绪）+ 情绪起伏；SFX 仅在确有强动作/真事件时极克制地用（默认不用）。

## 9. 转场
- **当前程度**：✅ beat 间 **0.3s 叠化**（`ffcmd.DISSOLVE_FADE`，xfade 链 + 独立旁白轨，时间轴精确对齐）。
- **已做 & 结论**：用户选叠化（比硬切柔和）。重构为「视频片段各+fade、xfade 重叠回去」保住 narration-driven 计时。0.3s 减轻"人脸叠人脸"鬼影。
- **失败/教训**：**剪辑点（J/L cut / 卡点）跳过**——一条连续旁白本身就有 L-cut 连贯感、没有音乐节拍可卡，人为错开反而破坏字幕对齐，低 ROI（适用于有对白/多机位/MV）。
- **后续方向**：相邻同人物特写时智能改短/换硬切减鬼影；按内容选转场类型（章节用叠化、章节内硬切）。

## 10. 调色（LUT）
- **当前程度**：✅ `lib/grade.py` 调色板，栏目级锁 **冷蓝晨光** 一个 look；`spike_run.py` 把这层套到所有**实拍镜头**（静图 + S2V + 卡片背景）。
- **架构（用户拍板 2026-06-29）**：调色 = **栏目级视觉签名**，不是每集让 LLM 自由挑——每集换色 = 系列散、没牌面。一个 look 锁死 = 品牌识别。一个 look 同时绑两半：① grade 滤镜（colorbalance+curves+eq），② 出图 STYLE_PREFIX（两者同管整片长相，必须一致，所以 `media_image.STYLE_PREFIX` 改为从 `grade.style_prefix()` 取，单一真源）。
- **已做 & 结论**：① **图表排除**（matplotlib 设计数据，套冷色白底发蓝、数字难读）——driver 里 chart 那支不传 grade，对照帧前后一模一样；② **卡片先调背景后烧字**（grade 进 `still_card_cmd` 的 ass 之前），背景变冷而金色条/白字纹丝不动（已验）；③ 嵌入渲染链（zoompan→grade→ass，curves 带空格用单引号包）能正常出片，先单帧验再跑整片。
- **失败/教训（重要）**：**uniform grade 只"套同一层色调"，不消除镜头间的相对冷暖漂移**——金光镜 vs 冷内景套同一滤镜后，金的还是相对更暖。用户实测"效果不明显"——这是**克制取舍的预期结果**（调重了就像滤镜、破坏"平静电影感"调性）。要真把漂移压平，得上**每镜自动白平衡**（见后续），那是另一档更狠的活，不是 uniform grade 能给的。
- **后续方向（按需求优先级）**：
  1. **每镜自动白平衡**（gray-world / 直方图归一）——真正消除冷暖漂移；uniform grade 之上的独立一步，效果明显但风险高（可能洗掉刻意的暖调晨光）。
  2. **强度可调** + 浓淡分档：现参数偏轻，进 config 让栏目按需调浓/淡。
  3. **LLM 立项时推荐 look**：Stage 1 栏目立项，AI 从调色板推荐一个、人拍板锁；不是每集 re-roll。
  4. **lut3d / .cube 外部 LUT**：接专业调色 LUT 文件（现用 curves/colorbalance 程序化，够 POC；专业级上 .cube）。
  5. 暖金 / 橙青两个备选 look 已在板里（`grade.LOOKS`），换栏目改 `SERIES_LOOK` 即可。

## 11. 片头/片尾卡
- **当前程度**：✅ 设计版 **B** 并入 pipeline（`lib/cards.py` 纯 ASS 构建器 + `ffcmd.still_card_cmd`/`silence_mp3_cmd` + `spike_run.py` 接线）。
- **已做 & 结论**：v1（文字叠照片）缺设计感 → B = **AI 按主题出背景（主体偏位、留白给字）+ 代码设计层**（分栏、金色色条、类型层级、统一强调色）。结尾卡 = **"本期3要点"总结卡**（可截图、有获得感、利传播）。**AI 出图只管背景，做不了版式/文字**（AI 写字乱码）。
- **接线要点（并入时实测）**：① 卡是 video-only clip，和 beat 一样进 `xfade_chain_cmd`（clip 长 = 卡时长 + DISSOLVE_FADE）；② 卡无旁白 → narration 轨前后补**等长静音 mp3**（mono/32k 对齐 TTS，否则 concat demuxer 错时），不然 mux `-shortest` 截掉卡；③ **字幕 `start_ms` 预偏移 `TITLE_DUR`**，否则全轨字幕早漂 2.6s（首句应在 0:00:02.60，已验）；④ 背景一遍过烧字（Ken Burns + `ass=` 同 `-vf`），不用两道 ffmpeg。复用钩子 `SPIKE_CARD_TITLE_BG/END_BG`。
- **后续方向**：文案/要点/栏目名进 Stage 1 config；要点由分镜那步从台词自动汇总（现手写占位）；想更高一档上 **C（HTML/CSS 模板渲染）**设计自由度拉满。

## 12. 封面（thumbnail）
- **当前程度**：⬜ 约定 title/end 定稿后做。
- **已做 & 结论**：封面=信息流里没点开时那张图，决定**点击率**，比 title card 更值钱。与 title card 是两个东西。

## 13. 镜头节奏
- **当前程度**：✅ 分镜按内容定每段镜头数 + 每镜停留：金句/点题 → 1 个长留镜（pace=hold），信息密/列举 → 2~4 个快切镜（pace=quick）。`storyboard.PACE_WEIGHTS`(hold2/normal1/quick0.6) → `ffcmd.shot_durations` 按权重分配 clip_len。
- **已做 & 结论**：① **最短停留地板** `ffcmd.MIN_DWELL=0.8s`：`max_shots(clip_len)` 限镜头数、`shot_durations` 权重切若任一镜 < 0.8s 退回等分——快切不会闪成故障；② 变化只在 beat 内部重切，beat 总长仍 = 旁白+fade，**时间轴/字幕不变**（长片 14 clip 实测 drift 仍 0.03s，未因镜头变多变差）；③ 避相邻雷同写进 prompt（相邻景别/机位必须不同、不连续两正脸）。
- **失败/教训（与 #14 联动）**：金句段被切成"1 个长留镜"后，AI 多把长留镜给了**人物** → 单脸停 5~7s，**反而加重"大B脸"**（实测长片 人8:空4，空镜仅 33%）。节奏与空镜比例耦合：**hold 镜不该默认是人脸**。→ 见 #14 / POC8。
- **后续方向**：分镜判官显式输出每 beat 镜头数与时长预算；列举类内容若是图表段（如四档配速）则快切显不出来，靠脚本层安排强列举到非图表段。

## 14. 空镜/人物镜比例
- **当前程度**：✅ 不设出镜配额，改用**内容忠实**：每段画它讲的事物，概念/数据/列举→空镜，人物正脸只留给开场/结尾直接对话、靠表情的金句、或讲教练本人动作。比例自然涌现。
- **失败/教训（重要）**：先试了**硬配额**（空镜≥50%），结果钝器两头甩——从 人8:空4(33%) 直接甩到 空17:人3(85%，主讲人几乎消失)。配额是错的工具：它跟内容打架。**用户点破**：分镜本就按内容拆，不该规定出镜率；大B脸的真因是模型偷懒，把不需露脸的解说句默认成"教练正脸讲话"（content-faithfulness 失败），不是空镜不够。
- **结论**：改成内容忠实 + 明确"何时才该露脸"后，长片实测 人5:空9(空镜64%)，脸落在开场(b00)/金句(b02,b06)/结尾(b11)——全是该有人的点，其余全空镜。比例随脚本自然变，不写死。
- **后续方向**：列举类内容若落在图表段（如四档配速）则快切显不出（见 #13）；脚本层可把强列举安排到非图表段。

## 15. BGM 响度 / ducking
- **当前程度**：✅ `mux_final_ass_cmd` sidechaincompress + amix；`spike_acceptance.measure_gap` 实测 gap，校准循环保证 ≥18dB。
- **已做 & 结论**：用户历史痛点（让调小也偏大）→ 写死 dB + 实测，不靠提示词。占位 pad 当前 gap 30–40dB。
- **POC4 后已知交互**：`measure_gap` 对整条 base.mp4 平均测响度；并入卡片后前后多 5.6s 静音区（BGM 不被 ducking 压），会让 gap 读数偏小。占位 pad 余量大（实测 35dB、一轮过）暂不受影响；**换真 BGM 时**要把测窗口收到旁白活跃段（`TITLE_DUR .. TITLE_DUR+Σ旁白`）再校。
- **后续方向**：换真音乐后重校（并改 measure_gap 测窗口，见上）；情绪段落动态音量。

## 16. 时间轴 / 字幕对齐
- **当前程度**：✅ 用 **实测 mp3 时长**（ffprobe）驱动 srt + 视频，不用 API 报的 audio_length。
- **失败/教训**：API 报的 audio_length 比真实 mp3 长几十 ms，srt 用报的、视频用真的 → 88s 漂 0.63s。改用实测后 drift 0.03–0.04s。叠化重构后仍保持。
- **后续方向**：字级时间戳（卡拉OK式字幕）需要时再评估。

## 20. 引擎 / 环境（ffmpeg）

- **失败/教训**：**系统 brew ffmpeg 无 libass**（烧不了硬字幕，也无 drawtext）→ 用 libass 静态构建（evermeet，在 `~/.local/ffmpeg-libass/`，libass+freetype+harfbuzz，coretext 找到 PingFang）；driver/acceptance 用 `FFMPEG_BIN`/`FFPROBE_BIN` 指过去。**Stage 1 必须随附/定位 libass 版 ffmpeg**。

## 已确立的"调性原则"（避免反复试错）
1. **平静、电影感、旁白驱动**的知识片 —— 不要综艺/vlog 那套（音效、花字、快闪转场）。
2. **声音质感 = 旁白音色 + 真音乐**，不是 DSP、不是合成音效。
3. **设计感 = 代码设计层（版式/类型/强调色/体系）+ AI 背景**，AI 出图做不了版式文字。
4. **强调要选择性**（关键词、转场、动效）——满屏强调 = 没有强调。
5. **时间轴一律用实测时长驱动**，不信 API 报的值。
